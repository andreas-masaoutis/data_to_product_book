==============================================
How the project flows
==============================================

We start with an idea. It might be a for a green project or for an existing one. Let us assume that we already have the team.
We develop the idea further, up to having a set of user stories
Up to this point we have an idea about what the product should be doing. We have enough pieces of information in order to get a first rough sketch of the architecture.
We then decide what the mvp could be and set up a plan of how to build it.
We develop the solution, test, document, etc, given the definition of done.
Once we have the mvp, we showcase it to the stakeholders, we expose it to users, and get feedback from both sides.
We take stock of how we worked, what went well, what didn’t, and try to figure out how to improve.
We also take stock of how the product did, how the users found it, etc. 
We get back to the drawing board, to update our assumptions, deepen our knowledge, refine the backlog, and plan the next iteration.
Rinse and repeat.
