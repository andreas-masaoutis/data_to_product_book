########################
Interesting sources
########################

Change by Design, Revised and Updated: How Design Thinking Transforms Organizations and Inspires Innovation, 2019, by Tim Brown. Everything about finding what is worth to build. The book does not focus on software, but contains lessons and tools that can be directly applied to various fields.

Lean Software Development; and agile toolkit, 2003, Poppendieck and Poppendieck. The first extensive exposition of the Lean approach to software development.

Lectures on Lean-Agile Product Management. This is the public version of the 2020 remote syllabus developed for Info 290M Lean/Agile Product Management, a three-unit graduate class taught by Jez Humble at UC Berkeley’s School of Information. https://lectures.leanagile.pm/ and https://github.com/jezhumble/lapm-public-lectures/blob/gh-pages/index.md
Practices of an Agile developer, 2006, by Subramaniam and Hunt. This book is somewhat old, but not dated, in that it provides a lot of practical considerations of what agile software development is in practice.

The Art if Agile Development, 2008, by Shore and Warden. This is a collection of many practices, focusing substantially on eXtreme Programming. Since this framework lent most of its engineering practices to the agile movement, this is a really good broad overview of the field and a good first starting point.

Engineering Software Products - An Introduction to Modern Software Engineering, by Ian Sommerville, published by Pearson Education, 2020.
This is a great introductory book on Agile. Sommerville has authored one of the main academic textbooks on software engineering, titled 'Software Engineering', where the focus was on traditional projects and therefore Agile techniques had been a mere reference. Instead, in his latest book, Sommerville has brought product development using Agile techniques at the centre of attention. A must read as an academic introductory book.
In chapter 1, Sommerville gives a short historical explanation on why the concept of Project dominated the software engineering field since the 1970's and how the focus has changed to Product. These changes provide the canvas for the Agile movement.

Lean from the trenches; Managing Large-Scale Projects with Kanban, 2011, Henrik Kniberg. An exposition of Kanban. The really good part is that the book comes from the actual experience of using Kanban in practice, so the reader can get a pretty accurate idea of what Kanban in about in practice.

The pragmatic Programmer; from journeyman to master, 2000, Hunt and Thomas. Written already before the Agile Manifesto, this is the authors’ view on the original ideas that shaped the field.

Practices of an Agile Developer – working in the real world, Subramanian and Hunt, 2006. Part of the Pragmatic Programmer series, this book gives practical descriptions of various practices. There is even a ‘What it feels like’ paragraph in each chapter section.

User Stories Applied; for agile software development, 2004, Mike Cohn. The technique of ‘User Story’ is now well established and widely accepted in the industry, as a mean of gathering requirements. In this book Cohn gathers together the experience of using the technique and creates a definitive read that defined the field.

Agile Software Development; Principles, Patterns, and Practices, 2003, Robert C. Martin. There is a section devoted to the ways software can be organised; in here Martin exposes for the first time the ‘SOLID’ principles that guide software building from the ground up.

Implementation Patterns, 2008, by Kent Back. Focused on patterns and how to structure code so that its intention is clear to the reader.

Clean Code: a handbook of agile software craftmanship, 2009, Robert C. Martin. Everything about writing better code, easier to read, easier to maintain and modify. A must read. 

Test-Driven Development by example, 2002, by Kent Beck. This is the first exposition of the eponymous technique.

Refactoring; improving the design of existing code, 1999, by Fowler and Beck. Refactoring, a core agile practice, was presented and extensively cover in this book for the first time.

Agile Testing: a practical guide for testers and agile teams, 2009, by Crispin and Gregory. That is first book on testing specifically aimed at agile teams. From test-first principle, to how testing in agile is different, to automation, this book covers all bases.

More Agile Testing: learning journeys for the whole team, 2015, by Crispin and Gregory. Updates and goes beyond what was covered in the previous instalment of the series.

Continuous Integration: improving software quality and reducing risk, 2007, by Duvall, Matyas, and Glover. One of the first books that explicitly tackled the issue of having working software at all times with all the latest changes committed and fully tested. Most of these practices are now considered standard practice.

Continues Delivery: Reliable software with releases through build test and deployment automation, 2011, by Humble and Farley

Peopleware: productive projects and teams, 2013 (3rd edition), DeMarco and Lister. A different take on productivity; one that focuses on people and teams. Would you guess that, for example, the office environment affects productivity and software quality? Well, they show you the numbers.

Agile Product Management with Scrum - Creating Products that Customers Love, by Roman Pichler, published by Addison-Wesley, 2010
A comprehensive overview of the Product Owner role within the Scrum framework, with a lot of practical pieces of advice on how to perform this role.

Modern Technical Writing - An Introduction to Software Documentation, by Andrew Etter, self-published, 2016. A concise, lean introduction on writing software documentation. In its 80 pages it includes fundamental ideas and practical advice on how to build an efficient workflow.

Just enough software architecture: a risk-driven approach, 2010, George Fairbanks. Following the agile idea of ‘just barely good enough’, this book covers how teams can pragmatically create systems with the correct architecture.

Software Architecture for Developers: Technical leadership by coding, collaboration, architecture sketching and just enough up-front design, 2015, Simon Brown. A modern take on how agile teams can create systems without losing sight of the whole system architecture.

On Architecture Decision Records https://dev.to/kevinjalbert/start-now-architecture-decision-records-580
An overview of what ADRs are, and how to use them in documenting all important decisions
